Reference

CLI reference

wecom-calendar-cli syncs your WeCom calendars over CalDAV into a local SQLite store, then serves fast, agent-friendly queries over that data. Events carry a free-form, agent-maintained metadata layer for your own classification and cross-tool task links. Output is JSON with structured errors. NDJSON lists keep rows on stdout and emit pagination notices on stderr; pass the notice's next value as --cursor to continue. AGENT NOTE: a companion Skill ("wecom-calendar") carries the canonical usage, safety modes, and setup and is the source of truth for driving this CLI. If you are an agent, load that Skill before composing commands. Check status with `wecom-calendar-cli skill status`; install it with `wecom-calendar-cli skill install`. After a CLI upgrade, refresh the Skill and reload the agent context.

Generated from the command tree, so it always matches --help.

wecom-calendar-cli auth guide

Show offline credential acquisition guidance for this service

wecom-calendar-cli auth guide

Explain where the CalDAV password comes from, without touching the network or the credential store. WeCom issues the password in its mobile app and has no web page for it, so credential_url is empty unless a team configured a page of its own; no request is ever sent to that URL. Issuing a new password invalidates the previous one, and the instructions say when not to.

wecom-calendar-cli event list

List events in a time window from the local store

wecom-calendar-cli event list [flags]

List events overlapping the half-open window [from, to) from the local store. Run `sync` first to populate it; a staleness notice on stderr flags out-of-date data. --since <duration> looks back from now (24h, 7d). --from is an inclusive lower bound and --to an exclusive upper bound; each takes YYYY-MM-DD (midnight in the display timezone, Asia/Shanghai), an RFC 3339 instant with an offset, or now±duration. A calendar looks ahead, so a bound may lie in the future: --from now --to now+14d. --since cannot be combined with --from/--to, and --to requires --from. With no window flag the window is 30 days either side of today, on local day boundaries; with --from alone it ends 30 days ahead. Results are paginated: the JSON envelope carries `has_more` and a `next` cursor, and --format ndjson reports the same on stderr as `_notice.pagination`. Pass `--cursor <next>` with the same window to fetch the following page, or `--all` to return every match in one page (fine here since the query is local). A cursor needs fixed bounds: page with absolute --from/--to. A window relative to the current time (--since, now±duration) is rejected with --cursor; read it with --all instead.

Options

FlagDefaultDescription
--allfalsereturn every match in one page (no pagination)
--calendarrestrict to one calendar id
--cursorcontinue from a previous page's `next` cursor; needs the same fixed window
--fromwindow start, inclusive: YYYY-MM-DD, RFC 3339 with an offset, or now-7d (default 30 days ago)
--include-metafalseattach each event's custom metadata
--limit0page size (0 = default page size unless --all)
--sincelook back this far from now, e.g. 24h or 7d (a YYYY-MM-DD value is a deprecated alias of --from)
--statuskeep only these statuses, comma-separated (e.g. confirmed,tentative)
--towindow end, exclusive, same forms; may be in the future, e.g. now+14d; requires --from (default 30 days ahead)
--untildeprecated alias of --to

Examples

  wecom-calendar-cli event list --from 2026-07-01 --to 2026-08-01
  wecom-calendar-cli event list --since 7d
  wecom-calendar-cli event list --from now --to now+14d --calendar 1688853806313356 --format table
  wecom-calendar-cli event list --from 2026-01-01 --to 2027-01-01 --all

wecom-calendar-cli expand

Rebuild the expanded event-instances view

wecom-calendar-cli expand [flags]

Recompute event_instances from the stored events: expand recurring masters into occurrences (applying EXDATE and overrides) and fold the same event across calendars into one occurrence. Pure rebuild; runs automatically at the end of `sync`. Never touches your metadata. Occurrences are expanded over a window (default 2 years back to 1 year ahead). Pass --from/--to to widen it when you need to query further into the past or future; a query beyond the window prints a coverage notice on stderr. Each bound takes YYYY-MM-DD (midnight in the display timezone, Asia/Shanghai) or an RFC 3339 instant with an offset, and either may be given alone. A window set that way is remembered and reused by every later `sync`, so it survives the next refresh; run `expand` with no flags to forget it and return to the rolling default. There is no look-back --since here: a window ending now would drop every future occurrence.

Options

FlagDefaultDescription
--fromexpansion window start: YYYY-MM-DD or RFC 3339 with an offset (default 2 years ago); pins the window for later syncs
--sincedeprecated alias of --from (YYYY-MM-DD only; a look-back duration is rejected)
--toexpansion window end, exclusive, same forms (default 1 year ahead); pins the window for later syncs
--untildeprecated alias of --to

Examples

  wecom-calendar-cli expand
  wecom-calendar-cli expand --from 2018-01-01 --to 2030-01-01

A free-form key-value layer attached to events by uid, organized under namespaces. Use it for your own classification, notes, or links to tasks in any project-management tool — the schema assumes none. Sync never touches this layer, so re-syncing keeps your annotations.

wecom-calendar-cli sync

Sync WeCom calendars into the local store

wecom-calendar-cli sync [flags]

Pull calendars and events over CalDAV into the local SQLite store. Incremental by default (calendars whose change-tag is unchanged are skipped); --full rescans everything. Idempotent: re-running is safe and leaves the data unchanged. This never touches your event metadata.

Options

FlagDefaultDescription
--calendarsync only one calendar id
--dry-runfalsereport which calendars would be scanned, without writing
--fullfalseignore change-tags and rescan every calendar
--progressautoprogress on stderr: auto (a live line on a terminal, bounded JSON notices otherwise), none, or json

Examples

  wecom-calendar-cli sync
  wecom-calendar-cli sync --full
  wecom-calendar-cli sync --calendar 1688853806313356 --dry-run
